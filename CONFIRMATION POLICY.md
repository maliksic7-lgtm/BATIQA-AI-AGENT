Confirmation Policy

For operational requests, the system should confirm before creating a ticket when important information is missing or the action has meaningful operational consequences.

Example:

Guest:

"AC kamar saya rusak."

AI:

"Baik, saya bisa membuat laporan untuk tim Engineering. Boleh saya konfirmasi bahwa masalahnya adalah AC kamar tidak dingin?"

After confirmation:

Create Ticket

For simple low-risk requests where all required data is already available, confirmation may be concise.

Example:

"Tolong antar 2 handuk ke kamar 305."

AI:

"Baik, saya akan mengirimkan permintaan 2 handuk ke Housekeeping untuk kamar 305."

Then create ticket.
